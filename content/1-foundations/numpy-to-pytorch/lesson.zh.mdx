## 2. 张量和参数

**张量**（tensor）是 PyTorch 的数组。你在 NumPy 里学到的大部分东西在这里用法一样：`@`、`.shape`、`.sum(0)`、
切片、广播。新的有三点：

| | NumPy 数组 | PyTorch 张量 |
|---|---|---|
| 数的类型 | 默认 `float64`（大约 16 位有效数字） | 权重默认 `float32`（大约 7 位有效数字，内存省一半） |
| 放在哪里 | 内存 | `"cpu"`、`"cuda"`（NVIDIA GPU）或 `"mps"`（Apple GPU） |
| 梯度 | 没有 | 如果 `requires_grad=True`，`backward()` 会填好 `.grad` |

`nn.Linear` 里的权重创建时就带着 `requires_grad=True`，所以每次 `loss.backward()` 之后它们都有 `.grad`。
你的数据不需要它。

几乎每个人第一次都会犯一个错：两边存权重矩阵的方式不一样。
在 NumPy 里你写的是 `X @ W`，`W` 的形状是 `(inputs, outputs)`。`nn.Linear(in, out)` 用相反的布局存权重，
**每个输出一行**，计算的是 `x @ W.T + b`。比如，`nn.Linear(3, 5).weight` 的形状是 `(5, 3)`。

为什么每个输出一行？每一行是构成一个隐藏单元的那 2 个数，所以 `weight[3]` 就是关于第 3 个单元的全部。

和 NumPy 的形状完全一样。

同样的数，按相反的布局存放。只有两种情况要在意：在两边之间复制权重时，
或者打印 `.weight.shape` 却以为它是 NumPy 的布局时。这一关的 demo 把 NumPy 的权重复制到 PyTorch 里，

## 3. 模型是一个类

在实验台的 PyTorch 那一边，模型是一个对象 `model`，你像调用函数一样调用它：`model(X)`。
这个对象是一个**类**（class）的实例。类是一个盒子的配方：这个盒子保存自己的数和自己的函数。
比较一下第一层的两种写法：

```python
def layer(x, W, b):            # 函数：每次都要把权重传进去
    return x @ W + b

class Layer:                   # 类：盒子自己保存权重
    def __init__(self, W, b):  # 做盒子时运行一次：layer = Layer(W, b)
        self.W = W             # self 的意思是“这个盒子”
        self.b = b
    def forward(self, x):      # 计算，用的是盒子自己的权重
        return x @ self.W + self.b
```

PyTorch 的模型也是这样写的一个类，有四条规则：

1. `__init__` 搭好各个部件：`self.l1 = nn.Linear(2, 6)`。它的第一行永远是 `super().__init__()`（见下面的框）。
2. `forward(self, x)` 用这些部件算出输出。
3. `model(x)` 会替你调用 `forward(x)`。你从不直接写 `forward` 这个名字去调用它。
4. `model.parameters()` 收集你存成 `self.something` 的每个部件里的每个权重。优化器只更新
   `parameters()` 返回的东西。

```python
class XorNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.l1 = nn.Linear(2, 6)
        self.l2 = nn.Linear(6, 1)
    def forward(self, x):
        return self.l2(torch.tanh(self.l1(x)))

model = XorNet()
logits = model(X)              # 运行 forward(X)
```

## 4. `backward()` 是加上去，不是替换

初学者的大多数 bug 都来自这一条规则。`loss.backward()` 算出梯度，然后把它们
**加**到 `.grad` 里已有的值上。它从不清空 `.grad`。清零是你的事，
用 `opt.zero_grad()`。

为什么要加？一个参数可能在好几个地方用到，它的总梯度是各部分的和
（你会在支线 U3 自己实现这一点）。在一次反向传播里面，加是对的。但在训练的一步和下一步之间，
这意味着旧梯度会一直留着，直到你把它们清掉。

<Predict id="pred-forget" />

它的梯度是 $2(w x - y)\,x = 2 \times (2 - 6) \times 2 = -16$。

## 5. 不打招呼就广播的形状

PyTorch 的广播和 NumPy 完全一样。这很方便，但也藏着一个经典的 bug。模型给每个样本输出
一个分数，排成一列，形状是 `(4, 1)`。标签却常常存成扁平的，形状是 `(4,)`。

<Blank id="broadcast-shape" />

<Stuck q="我的损失看起来正常，可模型什么都没学到。为什么？">

检查一下送进损失的形状。`(4, 1) − (4,)` 不会报错：广播把两者都拉伸成一张
`(4, 4)` 的表，把**每个**预测值和**每个**标签都比了一遍。这张表的均值是一个数，
所以什么都不会崩，但它是个错的数，它的梯度也指向错误的方向。

修正只要一行：用 `y.reshape(-1, 1)`（在 PyTorch 里也可以用 `y.unsqueeze(1)`）把标签变成一列，
或者用 `pred.squeeze(1)` 把预测值压平。一个好习惯是：就在算损失之前，把 `pred.shape` 和 `y.shape`
打印一次。

</Stuck>

<Stuck q="为什么 `print(loss)` 显示的是 `tensor(0.6958, grad_fn=...)`，而不是一个数？">

`loss` 仍然是一个张量，它记得自己是怎么算出来的（那就是 `grad_fn`），这样 `backward()` 才能用它。
要得到一个普通的 Python 数，写 `loss.item()`。打印和记录日志时都用它。

不要在训练的各步之间把张量本身存进列表，比如 `history.append(loss)`。每个张量都留着自己的
整张计算图，内存会一步一步涨上去。改成 append `loss.item()`。

</Stuck>

</Gate>

    loss.backward()
    opt.step()
