## 1. softmax 的反向传播

softmax 把分数 $z$ 变成概率 $p$：

$$
p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}
$$

反向传播收到 $dp$，也就是损失对每个 $p_i$ 的梯度，它要返回 $dz$。
新的地方在于：每个分数都会影响**每一个**概率，因为它们共用同一个分母
（分数线下面的那个和）。如果 $z_1$ 变大，$p_1$ 变大，$p_0$ 和 $p_2$ 就变小，总和保持为 1。

所以这些斜率组成一张表。第 $i$ 行第 $j$ 列放的是 $\partial p_i / \partial z_j$：$z_j$ 变动时，$p_i$ 变得有多快。
这张装着所有斜率的表就是**雅可比矩阵**（Jacobian）$J$。softmax 的雅可比矩阵有个简短的公式：

- 在对角线上，$J_{ii} = p_i (1 - p_i)$；
- 在对角线外，$J_{ij} = -p_i \, p_j$。

两行合起来：$J = \text{diag}(p) - p^\top p$。这里 $\text{diag}(p)$ 是对角线上放 $p$、其他地方都是 0 的表，
$p^\top p$（`np.outer(p, p)`）是所有乘积 $p_i p_j$ 组成的表。这门课里向量是行，所以 $p^\top p$ 是
`(n, 1) @ (1, n)` → `(n, n)`。

取 $z = [\ln 2, 0, 0]$。那么 $e^z = [2, 1, 1]$，和是 4，$p = [0.5, 0.25, 0.25]$。

<Deeper title="这两个公式是怎么来的">

记 $s = \sum_j e^{z_j}$，于是 $p_i = e^{z_i} / s$。$z_i$ 变动时，$e^{z_i}$ 和 $s$ 都会变，而且变化率一样，都是 $e^{z_i}$。
用分式的求导法则得到

$$
\frac{\partial p_i}{\partial z_i} = \frac{e^{z_i} s - e^{z_i} e^{z_i}}{s^2} = p_i - p_i^2 = p_i (1 - p_i).
$$

另一个分数 $z_j$ 变动时，只有 $s$ 会变：$\partial p_i / \partial z_j = -e^{z_i} e^{z_j} / s^2 = -p_i \, p_j$。

</Deeper>

### 从 dp 到 dz

每个分数 $z_j$ 都会影响每一个 $p_i$，所以 $dz_j$ 要从每个 $p_i$ 那里收一份：$dp_i \times J_{ij}$。
这就是支线 U3 里的 `+=`：一个值在好几个地方被用到，它的梯度就是所有份额之和。

$$
dz_j = \sum_i dp_i \, J_{ij}, \quad \text{that is,} \quad dz = dp \; J
$$

把 $J$ 的公式代进这个和，它就变短了。$dp \; \text{diag}(p)$ 就是 $dp_j \, p_j$，而 $dp \; p^\top p$ 是
$(dp \cdot p) \, p_j$，其中 $dp \cdot p$ 是整行共用的一个数。所以

$$
dz = p \odot (dp - dp \cdot p)
$$

其中 $\odot$ 表示逐元素相乘（NumPy 里的 `*`）。先从 $dp$ 的每个元素里减去同一个数 $dp \cdot p$，再乘以 $p$。

用 $p = [0.5, 0.25, 0.25]$ 和 $dp = [1, 1, 0]$，两种算法都验证一下：

- 长的算法：$J$ 的第 0 列是 $[0.25, -0.125, -0.125]$，所以 $dz_0 = 1 \times 0.25 + 1 \times (-0.125) + 0 \times (-0.125) = 0.125$；
- 短的算法：$dp \cdot p = 0.5 + 0.25 + 0 = 0.75$，所以 $dz_0 = p_0 (dp_0 - 0.75) = 0.5 \times 0.25 = 0.125$。

而每个头有 1000 行。简短形式从来不建 $J$。

### 用 NumPy 写，并检验

在注意力里，softmax 沿着表的每一行做，所以每一行都要算一次 `dp·p`：沿最后一个轴求和。
沿一个轴求和通常会去掉这个轴：对一个 `(2, 3)` 的表，`.sum(axis=-1)` 得到形状 `(2,)`。
参数 `keepdims=True` 会把这个轴保留下来，大小为 1，于是结果是 `(2, 1)`，每行一个数。
这样广播就能把它从它所在那一行的每个元素里减掉。

怎么知道反向传播写对了？和数值斜率 $(L(z + h) - L(z - h)) / 2h$ 比一比，就像第 6 关和支线 U5 里那样。
有一个损失让检验特别方便：$L = \sum dp \odot \text{softmax}(z)$，它在 $p$ 处的梯度正好是 $dp$。模板会替你做这个检验。

## 2. 一个注意力头的反向传播

一个头的前向传播（第 14 关）只有三行。下面是它们的形状，共 $L$ 个 token：

| 前向传播 | 形状 |
|---|---|
| `S = Q @ K.T / √dₖ` | `(L, dₖ) @ (dₖ, L)` → `(L, L)` |
| `A = softmax(S)`，每一行 | `(L, L)` |
| `O = A @ V` | `(L, L) @ (L, dᵥ)` → `(L, dᵥ)` |

反向传播按相反的顺序处理这几行，从最后一行开始。它从 `dO` 出发，`dO` 的形状和 `O` 一样。
所有的活只靠两条规则：

- **矩阵乘积** $Y = X W$（第 6 关）：`dX = dY @ W.T`，`dW = X.T @ dY`。
- **softmax**，每一行：第 1 节的公式，把 $p$ 换成 $A$。

下图给出顺序。每个梯度的形状都和它对应的值一样，所以转置很容易检查：

| 梯度 | 来自 | 形状 |
|---|---|---|
| `dV` | `O = A @ V` | `(L, dᵥ)` |
| `dA` | `O = A @ V` | `(L, L)` |
| `dS` | `A = softmax(S)` | `(L, L)` |
| `dQ` | `S = Q @ K.T / √dₖ` | `(L, dₖ)` |
| `dK` | `S = Q @ K.T / √dₖ` | `(L, dₖ)` |

### 手算一个例子

两个 token，$d_k = 4$（所以 $\sqrt{d_k} = 2$），$d_v = 2$。查询和键特意选得让每个分数都是 0：

$$
Q = \begin{bmatrix} 1 & 1 & 0 & 0 \\ 0 & 0 & 1 & 1 \end{bmatrix} \quad
K = \begin{bmatrix} 1 & -1 & 0 & 0 \\ 0 & 0 & 1 & -1 \end{bmatrix} \quad
V = \begin{bmatrix} 2 & 0 \\ 1 & 1 \end{bmatrix}
$$

$Q$ 的每一行和 $K$ 的每一行的点积都是 0，所以 $S$ 全是 0，$A$ 里每个权重都是 0.5。
每一行输出都是 $V$ 各行的平均：$O = [[1.5, 0.5], [1.5, 0.5]]$。
从上面各层传来的梯度是 $dO = [[1, 0], [0, 2]]$。

## 3. 反向传播必须在 GPU 显存里留下什么

再看一遍那五行反向代码。每一行都用到了前向传播的值：`A`、`V`、`K`、`Q`。
反向传播走到它们时，这些值必须还在，所以前向传播要把它们留下来。这些留下来的值叫作
**保存的激活值**（saved activations）。在你的代码里，它们就是元组 `saved`。

</Gate>

<Gate requires="pred-saved">

所以一个头会保存 `Q`、`K`、`V` 和 `A`，其他层也保存各自反向规则需要的东西（比如每个
矩阵乘积的输入）。训练从两个方面占用 GPU 显存。

### 按参数算：固定的开销

大模型用混合精度训练（支线 U2）。前向和反向传播用 16 位的数，bfloat16（简称 bf16）。
更新则在一份 32 位的 float32 副本（简称 fp32）上做，这样微小的变化不会被舍入吃掉。用 Adam（第 7 关）时，每个参数需要：

| 每个参数都要保存 | 格式 | 字节 |
|---|---|---:|
| 前向和反向传播用的权重 | bf16 | 2 |
| 它的梯度 | bf16 | 2 |
| 权重的主副本 | fp32 | 4 |
| Adam 的 m | fp32 | 4 |
| Adam 的 v | fp32 | 4 |

每个参数一共 16 字节，和批大小、序列长度都无关。

### 按 token 算：激活值

保存的激活值随批里的数据增长。它们大多每个 token 一行，形状是 `(B, L, d_model)`：当 $B = 4$，$L = 1000$，
`d_model` = 1000，每个数 2 字节时，一个这样的张量是 8 MB。一层会保存好几个这样的张量，比如
它的各个矩阵乘积的输入。注意力权重 `A` 不一样：每个头里，每一对
token 都有一个数。它的形状是 `(B, h, L, L)`。

<Deeper title="重计算：多算一些，少占显存">

前向传播不必什么都保存。用**重计算**（recomputation），每一层只保存自己的输入。反向传播
走到这一层时，从输入出发把这一层的前向传播再跑一遍，拿回那些值，马上用掉。

在上面的例子里，一层只需保存一个 `(4, 1000, 1000)` 的输入，8 MB；否则光是 `A` 就要 64 MB，还有其他所有东西。
反向传播在某一层里时，这一层的值会重新出现，所以峰值是保存的各层输入，再加上一层的值。
代价是多跑一次前向传播。一次反向传播的计算量大约是前向的两倍。所以一个训练步从 1 + 2 = 3 份
计算变成 3 + 1 = 4 份：计算量多了约 33%，显存却省了很多。

这里的 kernel（算子）是在 GPU 上运行的一个程序。融合算子在一个程序里做好几步。
融合注意力算子比重计算还要省显存。它们保存 `Q`、`K`、`V`、`O` 和每行一个数（来自 softmax 的那个和），但不保存 `A`。
它们在反向传播时分成小块重新算出 `A`，所以不保存任何 $L \times L$ 大小的东西。课程后面会搭出这个。
softmax 这一步仍然需要每一行的 $dA \cdot A$，而它只用 `O` 和 `dO` 就能得到：
$dA = dO \, V^\top$，所以 $\sum_j dA_{ij} A_{ij} = \sum_c dO_{ic} \sum_j A_{ij} V_{jc} = \sum_c dO_{ic} O_{ic}$。
在第 2 节的例子里，第 0 行给出 $dO \cdot O = 1 \times 1.5 + 0 \times 0.5 = 1.5$，而 $dA \cdot A = 2 \times 0.5 + 1 \times 0.5 = 1.5$。
