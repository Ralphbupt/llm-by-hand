学完第 13 关，每个词都是一串数。可是“bank”在“river bank”和“bank account”里的那串数是一样的。
一个词需要用上它周围那些词的信息。**注意力**（attention）就是做这件事的办法：每个词都把句子里的所有词
按它自己算出来的比例混合起来，得到一个新向量。

这是 Transformer 最重要的部分。这一关一小步一小步地把它搭起来，始终只用三个词，每个词两个数。

## 1. 为什么不从左往右读就行了？

在注意力出现之前，读一句话的常见办法是**循环神经网络**（RNN）。它一次读一个词，
并保留一份到目前为止所有内容的摘要，也就是隐藏状态 h。每来一个新词 $x_t$，就更新它：$h_t = \tanh(w\,h_{t-1} + x_t)$
（这是支线 N3 里 RNN 的单个数的版本）。

这种设计有两个问题：

1. **大小固定。** 读到第 50 个词时，前面 49 个词的所有信息都得塞进同样那几个数里。
2. **越早的词越弱。** 第一个词的影响要经过后面的每一步才能到达结尾，而每一步
   都要乘上 w（还要乘上 tanh 的斜率，它从不超过 1）。所以当模型把句子结尾预测错了时，
   修正几乎传不到第一个词，训练也就学不会用上它。

<Blank id="rnn-fade" />

<Gate requires="rnn-fade">

下面是 w = 0.5 时它缩小得有多快：

| 往后几个词 | 第一个词的影响要乘上 |
|---|---|
| 1 | 0.5 |
| 2 | 0.25 |
| 5 | 0.0312 |
| 10 | 0.000977 |
| 50 | 8.88 × 10⁻¹⁶ |

几十个词之后，句子开头的影响几乎为零。注意力的做法正好相反：
每个词都**直接**看其他每个词，一步到位，不管隔多远。对第 50 个词来说，读第一个词
和读第 49 个词一样容易。这一关剩下的部分就来搭建它。

经典网络分支会搭一个 RNN 和一个 LSTM（支线 N3 和支线 N4），完整地展示这种缩小。支线 N5
在一个真实的任务上测量这个问题：一份 32 个数的摘要，在 20 位数字串的反转任务上正确率是 0%。N5 还用单个提问向量
算出了第一个注意力。这一关加上矩阵 `W_Q`、`W_K`、`W_V`，让每个词都能提问。

</Gate>

## 2. 加权平均

三个词：cat = [2, 0]，dog = [1, 1]，car = [0, 2]。注意力做三件事：

1. **分数。** 每个词和每个词做点积：`scores = X @ X.T`。点积大表示“这两个指向同一方向”。
   实验台接着把每个分数除以 √2。现在先把它当成一个固定的缩放；第 5 节会解释为什么。
2. **权重。** 用 softmax 把每一行分数变成加起来等于 1 的比例。
3. **输出。** 每个词的新向量是所有词的加权平均：`output = weights @ X`。

## 3. Q、K、V：每个词的三个版本

到目前为止，每个词都用同一个向量做三件事。在真正的 Transformer 里，每个词会做出自己的三个版本，
办法是乘以三个学出来的矩阵：

- **Q = X @ `W_Q`**，查询（query）：这个词在找什么。
- **K = X @ `W_K`**，键（key）：其他词拿自己的查询来比较的标签。
- **V = X @ `W_V`**，值（value）：别的词看这个词时，它交给输出的东西。

“a 看 b”的分数现在是 a 的查询 · b 的键。

然后一切照旧：`attention(Q, K, V) = softmax(Q @ K.T / √d_k) @ V`。

分数（以及权重）只用到 Q 和 K。`W_V` 不改变*谁*被看，它改变的是复制*什么*。
按“V 只保留 x”：权重完全不变，但每个输出都丢掉了它的 y 那个数，

<Deeper title="为什么不只用一个矩阵？">

分数 `q_a · k_b` 等于 `x_a W_Q W_Kᵀ x_bᵀ`。所以分数只取决于乘积 `W_Q W_Kᵀ`，这里是一个 2×2 的矩阵。
如果这个乘积是对称的，分数也是对称的。这就是“交换键”仍然给出对称的表的原因：
交换矩阵是对称的。“单向的键”不是，所以 cat 可以看 car，而 car 不回看。

把乘积拆成 `W_Q` 和 `W_Kᵀ`，还能让模型在一个比词向量本身（`d_model` 个数）更小的空间
（`d_k` 个数）里比较词。第 15 关会利用这一点，并排运行好几个注意力。

</Deeper>

</Gate>

## 4. 没有人设计这些矩阵

第 3 节里的矩阵是手写的。在真实的模型里没有人写它们：它们是学出来的，就像
第 2 关学出一条直线那样。下面是最小的版本。两个词，apple = [1, 0]，sweet = [0, 1]。
任务：sweet 的输出应该是 apple 的内容 [1, 0]。`W_K` 和 `W_V` 是单位矩阵，
`W_Q` = [[0, 0], [c, 0]]：只有左下角那个数 c 可以变。
于是 sweet 的查询是 [0, 1] @ `W_Q` = [c, 0]，所以 c 决定 sweet 看 apple 看得有多用力。
实验台用第 2 关的平方误差衡量和目标值的差距，两个数的误差加起来：
loss = (`out_x` − 1)² + (`out_y` − 0)²。梯度下降改变 c，让损失变小。

<Predict id="knob-forever" />

Q、K、V 是事先训练好的吗？不是。模型里有两种不同的数，只有一种是训练出来的。

| 种类 | 例子 | 从哪里来 | 和模型一起保存吗？ |
|---|---|---|---|
| 参数 | `W_Q`、`W_K`、`W_V`、嵌入表 | 一开始是随机的；训练改变它们 | 保存，训练后固定不变 |
| 激活值 | Q、K、V、分数、权重、输出 | 模型每次运行时从输入 X 算出来 | 不保存：每次运行后就删掉（训练时会留到反向传播用完） |

所以 `W_Q` 存在模型里；Q 不存。给模型一句新话，同一个固定的 `W_Q` 会算出一个新的 Q。
（第 18 关会讲一个例外：写长文本时，前面那些词的 K 和 V 会保留一段时间，这就是 KV 缓存。）

在新的输入上运行训练好的模型叫作**推理**（inference）：参数固定不变，输入把每一层
都走一遍，模型给出输出。注意力是这次运行中每一层里的一步。**训练**也走同样这些步骤，然后
把输出和目标值比较，再改变参数。

<Predict id="infer-change" />

<Stuck q="目标值是一种注意力模式吗？我们会告诉模型该看哪里吗？">

不会。损失比较的是 sweet 的**输出**和 [1, 0]。权重从不出现在损失里。训练一直改 c，直到
输出对了为止。权重也跟着变了，但只是因为 c 变了。

目标值来自任务。在这个实验台里它是给定的。在语言模型里，它本来就在文本中：下一个词
（第 11 关）。从来没有人写下“这个词应该看那个词”。

</Stuck>

<Deeper title="把 `W_V` 也训练：同样的损失，不同的注意力">

实验台只训练 c，`W_V` 保持不变。如果 `W_Q`、`W_K` 和 `W_V` 都训练呢？`demo.py` 做了四次：

| 训练的是什么 | sweet 放在 apple 上的权重 | 损失 |
|---|---|---|
| `W_Q` 和 `W_K`（`W_V` 固定为单位矩阵） | 1.00 | 0.0000 |
| 三个都训练，从单位矩阵开始 | 0.52 | 0.0000 |
| 三个都训练，随机开始（随机种子 0） | 0.16 | 0.0000 |
| 三个都训练，随机开始（随机种子 1） | 0.73 | 0.0000 |

每次都得到正确的输出，但注意力权重完全不同。当 `W_V` 可以变时，V 也能让
“看 sweet”给出 [1, 0]。所以一张注意力图只是得到同样输出的许多方式之一。热力图显示的是一个
训练好的模型做了什么，而不是它必须怎么做。读热力图时要小心。

</Deeper>

## 5. 为什么要除以 √`d_k`

到目前为止，每个分数在 softmax 之前都除以了 √`d_k` = √2。（`d_k` 是每个查询和每个键里数的个数，这里是 2。）
不除会怎样？

<Gate requires="knob-forever">

<Blank id="unscaled-self" />

验证一下：在第一个实验台里取消勾选“把分数除以 √`d_k`”，看 cat 那一行。

不除的话，权重会更尖锐。每个词两个数时，这个影响很小。
有 64 或 512 个数时，影响就很大了：点积要把 `d_k` 项加起来，所以它会随 `d_k` 增大。
对很大的数做 softmax，几乎所有权重都落在一个词上，这时用来训练 `W_Q` 和 `W_K` 的梯度几乎消失。

<Deeper title="分数会变得多大？">

取随机的查询向量和键向量，它们的数的标准差（std）是 1。它们点积的标准差是 √`d_k`：

| `d_k` | q · k 的标准差 | 除以 √`d_k` 之后 |
|---|---|---|
| 2 | 1.42 | 1.01 |
| 64 | 8.08 | 1.01 |
| 512 | 22.55 | 1.00 |

除以 √`d_k` 能把分数的标准差拉回 1，不管 `d_k` 是多少。`demo.py` 会打印这张表。

</Deeper>

</Gate>
