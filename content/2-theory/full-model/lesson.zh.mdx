现在你手里有了所有部件：嵌入、注意力、掩码、FFN、残差和 LayerNorm，第 16 关又把它们组装成了
一个解码器块。这一关你要把这些块堆成一个完整的模型，看它在一个真实的任务上工作。

任务是：**把一个数用英文读出来。** 输入是一串数字，输出是英文单词。
模型把两者看成**一个序列**：先是数字，然后是 `=`，然后是单词，最后是 `<eos>`（“结束”）。

```
4 2 7 = four hundred twenty seven <eos>
```

模型从头到尾只做一件事：猜下一个 token。给它 `4 2 7 =`，它就接着这个序列往下写，一次一个词，
直到写出 `<eos>`。你给它的那部分是**提示词**（prompt）；它写出的那部分是答案。

一共有 1,000 个数，从 0 到 999。模型在其中 900 个上训练。另外 100 个留出来（模型从不在它们上面训练），
所以要答对它们，唯一的办法是学会规则，而不是记住答案。

## 3. 一次一个词

第 14 关把它叫作**推理**（inference）：运行一个训练好的模型来得到答案。它就是整个前向传播，从 token id 到
logits，所有权重都固定不变。训练运行同样的前向传播，然后做反向传播，再改动权重。

<Predict id="infer-vs-train" />

模型从不一次写出整个答案。它写**一个词，然后再运行一次**：

1. 从提示词开始：数字和 `=`。
2. 在目前为止的所有内容上运行模型。输出每个 token 一行。
3. 只有**最后一行**有用。输出层把它的 64 个数变成 42 个分数，每个 token 一个。
   这些原始分数通常叫作 **logits**。
4. 选分数最高的那个（这叫贪心解码），把那个 token 加到末尾。
5. 重复，直到模型选出 `<eos>`。

## 4. 它是怎么学会的

训练时，模型**不是**一次一个词地运行。它拿到整个序列，一次前向传播就做出所有的猜测。
输入 x 是去掉最后一个 token 的序列，目标 y 是去掉第一个 token 的序列：

```
427:    x   4  2  7  =     four     hundred  twenty  seven
        y   2  7  =  four  hundred  twenty   seven   <eos>
```

因果掩码让每个位置看不到它要猜的那个 token。像这样用正确的前文来训练，
而不是用模型自己猜出来的前文，叫作**教师强制**（teacher forcing）。

<Stuck q="为什么 x 和 y 是同样的 token，只是错开了一位？">

因为位置 t 要猜的是下一个 token。把它们上下对齐写出来：`=` 下面的答案是“four”；
“four”下面的答案是“hundred”。y 就是 x 往左挪一步，末尾加上 `<eos>`。

如果你把同一行既当输入又当目标，位置 t 就可以直接抄它自己的输入，
损失会降到零，而模型什么都没学到。

</Stuck>

不是每个猜测都值得学。4 下面的目标是 2，2 下面的目标是 7：模型是在猜题目里的
数字，而这些数字是随机的。只有是单词或 `<eos>` 的目标才是答案。
它们前面的每个目标，包括 `=`，都是题目的一部分。损失只计入答案的目标，跳过其余的：做法是把要跳过的目标设成 PAD。

<Blank id="count-427" />

<Gate requires="count-427">

训练在每批 64 个数上重复四步：

```python
for x, y in batches:              # 1. 一批数据；跳过的目标是 PAD
    logits = model(x)             # 2. 前向传播：(64, L, 42)
    # 3. 损失，ignore_index=PAD
    loss = loss_fn(logits.reshape(-1, 42), y.reshape(-1))
    # 4. 反向传播，然后更新
    opt.zero_grad(); loss.backward(); opt.step()
```

短的数，序列也短。在一批 0 到 63 的数里，最长的 x 是 5 个 token（比如
`2 3 = twenty three`），所以 logits 是 (64, 5, 42)，一共有 320 个目标。其中只有 167 个计入：118 个是数字
或 `=`，35 个是短序列后面的 PAD。

<Blank id="reshape-rows" />

<Stuck q="为什么非要 reshape 成 (B × L, V)？">

损失函数要的是一个简单的猜测列表：每个猜测一行分数，每个猜测一个正确的 id。
它不关心一个猜测来自哪个序列、哪个位置。
每个序列的每个位置都是一个独立的猜测，所以 (64, 5, 42) 被存成 320 行，每行 42 个数。

</Stuck>
