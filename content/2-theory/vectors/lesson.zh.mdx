第 12 关把文本变成了 token id。把 `hello` 切成字符，词表是 e、h、l、o（id 0 到 3），
这个词就变成 `[1, 0, 2, 2, 3]`。

网络不能直接用这些 id。它会把它们当成数量：`l`（2）会是 `h`（1）的“两倍”。
所以每个 id 都换成一小串数，也就是一个**向量**（vector），从一张表里查出来。这叫**嵌入**（embedding）。

## 1. 嵌入表

这张表**每个 id 一行**。嵌入一个 token，就是取出它的那一行。这里每行有 2 个数；
真实的模型有几百到几千个。所以一句 L 个 token 的话会变成形状 (L, d) 的数组：每个 token 一行。

## 2. 比较两个向量：点积

既然相似的 token 会得到相似的向量，你就需要一个数来表示“有多相似”。最简单的是
**点积**（dot product）：把两个向量逐个数相乘，再加起来。你在第 1 关就做过这件事：
它就是矩阵乘法里的一格。

cat·car 一开始正好是 0：cat 和 car 成直角。现在不动 dog，让 dog·car 正好等于 0。然后把 dog 沿同一个方向拖得离中心更远。
它和 cat 的点积变大了，但 cos(夹角) 不变。点积混合了两件事：
**方向**（夹角）和**长度**。

</TryIt>

<Deeper title="点积、长度和夹角">

对两个向量 $a$ 和 $b$：

$$a \cdot b = |a|\,|b|\cos\theta$$

两个向量指向同一方向时 $\cos\theta$ 是 1，成直角时是 0，方向相反时是 −1。
把点积除以两个长度，只剩下夹角那部分，叫作**余弦相似度**（cosine similarity）。

下一关的注意力用的是普通的点积。长度在那里有影响：越长的向量，分数越大。

</Deeper>

## 3. 向量从哪里来？

这张表一开始是随机数，训练会移动它们。可是，是什么把“cat”和“dog”推到一起的？
道理很简短：**一个词的含义来自它周围的词**。cat 和 dog 出现在相同的位置（“the … sleeps”、
“my … is hungry”），所以一个要预测词的邻居的模型，给它们相似的向量效果最好。

只靠数数你就能看到这一点。拿四个很短的句子：“cat eats fish”、“dog eats meat”、“cat drinks milk”、
“car needs fuel”。对每个词，数一数 eats、drinks、needs 分别有几次紧挨着它（在它前面或后面一个词）。

## 4. 一个词一个向量还不够

查找表对同一个 token 总是返回同一行，不管它在什么句子里。
这对 **apple** 这样的词是个问题：它在一句话里是水果，在另一句话里是公司。

这里四个数有可读的含义：水果（fruit）、科技（tech）、甜（sweet）、动作（action）。表里 apple = [1, 1, 0, 0]：
水果上一个 1，科技上一个 1，因为同一行要同时服务两种含义。
拿两句话来看：“sweet apple”和“apple releases phone”。

现在用代码写出这一步，只改一处：词不一定同等重要。每个词有一个**权重**，
权重加起来等于 1，混合结果就是各行的加权和。权重相等（各 1/2，或各 1/3）就是
实验台里的普通平均。用一个 id 列表去索引表，会按这个顺序取出那些行：

```python
T = np.array([[1, 2], [3, 4], [5, 6]])
T[[2, 0]]                 # [[5, 6], [1, 2]]   第 2 行和第 0 行，形状 (2, 2)
0.75 * T[2] + 0.25 * T[0] # [4, 5]   权重 0.75 和 0.25：0.75·[5, 6] + 0.25·[1, 2]
```

每个词写一项，只适用于词数固定的情况。第 1 关有更短的写法：一个权重向量
`@` 一个矩阵，得到的正是它各行的加权和，行数多少都行。
